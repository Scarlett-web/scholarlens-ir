## 3. GitHub 协作

- 分支策略待会议确认；在确认前保持当前 `zjl`，不自动创建或切换分支。
- issue 模板至少包含背景、输入、输出、验收标准、负责人、截止日期和风险。
- PR 描述列出变更文件、协议影响、测试命令和结果；公共协议变更必须 @组长并请求另一位成员 review。
- 采用小步提交和可回滚配置；禁止提交 `*.pdf`、数据库、索引、模型缓存、`.env` 和依赖目录。
- 每日同步：各成员报告已完成、下一步、阻塞项；组长维护里程碑和风险表。
