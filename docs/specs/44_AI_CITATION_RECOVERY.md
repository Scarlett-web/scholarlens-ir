# 引用生成与有限修复契约

日期：2026-11-03。负责人：组长。

输入为原问题、已核对来源及当前对话；论文内容和模型草稿均是不可信数据。输出继续使用原有 answer/citations/evidence_status 接口。

- 模型可用当轮来源短编号 S1、S2 等引用；服务端只按当轮证据表映射回完整 chunk ID。存储、原文定位与接口引用继续使用原有完整 ID。不得猜测未知编号、改写引文或为错误回答补造引用。
- 引文仍必须逐字出现在对应原文片段内；正文引用必须与引用列表一致；比较仍要求逐篇覆盖。
- 校验失败最多修复一次。修复轮收到上一轮草稿及服务端生成的安全错误分类；草稿不得当作新证据，不进入成功响应或日志。修复失败继续保留证据，不发布不合格答案。
- 无论文范围的纯问候直接进入现有通用回答流程；研究问题、混合问候和带范围问题仍走研究流程。

验收：短编号映射和未知编号拒绝；伪造引文继续失败；修复轮携带草稿与错误且不泄露；纯问候不调用检索；原有比较、权限、会话与预算测试通过。真实模型验收需另行记录，受控测试不能代替。

## 有原文却落入通用问答（2026-11-03 补充）

用户复现：5 条来源通过核对，模型返回空的研究答案后被转入无证据通用回答，最终让用户自己提供论文；同时规划与通用正文均表现出输出不足。

- 原默认生成预算仅 800 tokens，规划上限 512。默认改为 8192，规划最多 4096，生成总上限 16384；管理员显式配置的小预算继续生效。上限放宽可能增加供应商用量与耗时，不代表每次都会用满。
- Chat Completions 的 finish_reason=length、Responses 的 max_output_tokens 中断必须返回可识别的 ai_output_truncated，不能把半截正文当作正常回答。
- 明确询问论文/文献或其上下文的研究问题，在已有已核对来源而模型拒答或返回空答案时，返回按论文去重的候选清单和真实原文引用，标记 evidence_only；不改走无证据问答，不声称已生成综合结论。用户可直接打开对应来源。模型真正异常的 warning 保留。
- 不涉及论文的闲聊、无检索结果的无范围问答继续允许明确标注的通用回答；指定范围、比较和总结保留原边界，不用候选列表伪装综合回答。
- 验收包含原问题的 HTTP 流程、真实原文候选逐篇去重及引用有效性、空研究答案不触发 general_answer、截断识别、显式预算和闲聊兼容。真实个人模型验收单独记录。

### 真实 Gemini 检索计划格式

实际 gemini-3.8-flash 响应为包在 JSON Markdown 围栏中的有效 queries 对象；旧计划解析器直接 json.loads 导致回退。计划与回答统一接受完整、可选 json 标签的代码围栏（允许外围空白），仍要求内部为 JSON 对象；不从任意解释文本中猜测或截取 JSON，不执行计划里的任意工具名。外层供应商协议仍要求原生 JSON。验收包括同型真实响应、无围栏兼容、解释文本/多个对象/过深内容拒绝和真实模型检索与引用流程。
