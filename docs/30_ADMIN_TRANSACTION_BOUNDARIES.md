# 管理员变更与事务边界

2026-10-28。负责人：项目维护者。本轮补验用户管理的角色限制及“至少保留一名有效管理员”的并发约束。仅使用独立SQLite和真实账户路由，不读写生产账户，不连接检索、邮件或供应商。

## 输入、输出与验收契约

- `PATCH /api/admin/users/{id}` 的角色/停用变更要求当前有效管理员身份；游客401、普通用户403、目标不存在404。不能禁用当前管理员自己。
- `POST /api/auth/deactivate` 仍要求当前会话和正确二次凭证；停用成功撤销本人会话、保留资料。错误二次凭证仍为 `401 invalid_credentials`。
- 至少保留一名有效管理员。并发降级、并发自停用或两者混合时，角色读取、有效管理员计数和实际变更必须处于同一写事务。不能让两个请求同时以旧计数放行；拒绝请求返回既有 `409 invalid_state`，不改变账户/会话。
- 管理员写操作获得事务后再次确认操作者角色及停用状态；自停用在事务内读取最新账户，不能依据事务之前的旧角色判断。
- 隔离验收包括游客/普通用户/管理员权限、顺序保护、并发保护、失败回滚及会话边界。并发测试只协调真实SQLite查询的时序，不替换账户路由、计数或写入结果。

- 修复在两个入口的检查/变更之前使用 `BEGIN IMMEDIATE`，管理员更新在锁内复核操作者，自停用读取最新角色。计数只保护当前有效的管理员；已经停用的管理员仍可正常降级，不误报最后管理员冲突。没有数据库结构、账号或检索索引迁移。
