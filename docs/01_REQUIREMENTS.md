# 01 需求清单与验收标准

## 1. 目标与用户

ScholarLens 面向需要查找和理解学术论文的学生、教师和项目演示者。系统必须以真实论文内容为依据，支持从 PDF 处理到检索、解释和问答的可追溯链路。上一届项目的常规功能作为背景参考，不作为本项目创新声明；本项目的提升点是现代 UI、混合检索、可验证 RAG 和量化评价。

### 开发顺序

`D-01 → D-02 → D-03 → D-04 → D-05/D-06 → D-07 → D-08 → D-09 → D-10~D-12 → D-13~D-16 → D-17~D-19`。任何 P1/P2 项都不得绕过 P0 数据协议和检索链路。若 1000 篇处理延迟，先交付可追溯的 20 篇闭环，再扩容。

## 3. 用户场景

1. 学生输入 `computer` 并选择 `title`，看到按 BM25 排序的分页结果、标题高亮和年份筛选。
2. 研究者选择语义或混合模式输入自然语言问题，比较关键词与语义结果，并查看匹配字段和分数解释。
3. 用户打开论文详情查看元数据、摘要、正文片段和 PDF；缺少字段时看到“原文未提供”，而不是猜测。
4. 用户在问答面板提问，系统只根据检索到的真实片段回答，并展示论文 ID、页码/片段定位；证据不足时明确提示。
5. 演示者在统计页查看数据量、解析成功率、索引时间、延迟和评价指标。

## 4. 非功能要求

- 可复现：固定配置、查询集、随机种子和命令；记录版本和运行条件。
- 可解释：结果返回字段、片段、高亮、检索模式和分数；RAG 返回来源。
- 可用性：接口错误使用统一结构，前端有加载、空结果、错误和无权限状态。
- 安全性：密钥不入库，上传和管理员功能需权限与大小限制；P2 可延期但必须标记。
