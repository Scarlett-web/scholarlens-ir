# 07 测试、评价与课堂演示

## 1. 测试矩阵

| 类别 | 输入 | 检查 | 负责人 | 证据 |
|---|---|---|---|---|
| 解析 | 20/1000 PDF | 成功率、失败原因、耗时 | A | JSONL、错误清单、统计报告 |
| Schema | 合法/缺字段/重复记录 | 类型、空值、唯一 ID | A | 校验命令和输出 |
| 六字段检索 | 每字段至少 2 条查询 | 命中、字段范围、空结果 | 组长 | 请求、响应、状态码 |
| 搜索体验 | 分页/高亮/年份/排序/模糊/短语 | 参数边界和 UI 状态 | B+组长 | 走查记录/截图 |
| 性能 | 固定数据量和查询集 | p50/p95 延迟、索引时间 | 组长 | 基准表、运行环境 |
| 语义/RRF | 标注查询集 | P@5、nDCG@10、Recall@k | A+组长 | 结果表和参数 |
| RAG | 可证据/无证据问题 | 引用可回溯、证据不足提示 | 组长+B | 问答记录、引用截图 |
| 回归 | 每次协议变更 | API/UI 不破坏 | 全员 | CI 或手工清单 |

## 2. 评价指标

- `Precision@5 = 相关结果数@5 / 5`；查询不足 5 条时按约定补零或单独报告。
- `nDCG@10` 使用 0/1 或 0/2 相关性标注，报告标注规则、查询数和平均值。
- 同一查询集、数据快照、过滤条件和候选数比较 BM25、语义、混合；记录模型名称、RRF `k`、ES 版本和硬件。
- 延迟至少报告 p50/p95、冷启动/热缓存状态、索引规模和并发条件；不可将 Mock 延迟当作真实结论。
- 解析质量报告成功率、核心字段完整率、重复数、正文长度分布和失败类型。

## 3. 测试查询集建议

准备覆盖 `title:computer`、作者名、年份、机构、地址、正文术语、短语和自然语言问题的固定查询；每条记录 `query_id`、查询、目标字段、相关文档 ID、相关等级、备注。真实论文内容可在数据到位后补齐。

## 4. 课堂演示流程（约 8—10 分钟）

1. 30 秒：介绍问题、数据规模和创新重点，说明哪些组件是拟议/已完成。
2. 90 秒：展示数据处理统计，打开一条 JSONL 记录和失败/缺失统计。
3. 2 分钟：输入 `computer`，演示全字段与 `title` 字段检索、BM25、高亮、分页和年份筛选。
4. 1 分钟：打开详情和 PDF，展示元数据、摘要、正文来源。
5. 2 分钟：同一问题切换 BM25/语义/混合，展示排名解释与指标表。
6. 2 分钟：对真实正文提问，点击引用回到论文；再演示证据不足提示。
7. 30 秒：展示架构图、团队分工、复现命令和已知风险。

## 5. PPT 分工

- 组长：问题定义、架构、检索方法、指标结果、进度与风险整合。
- 组员 A：数据来源说明、GROBID 流程、质量统计、评价查询集。
- 组员 B：UI 设计演变、页面走查、交互演示视频/截图。
- 全员：至少一次完整彩排；演示环境、数据快照和备用录屏由组长统一保管。

## 6. 风险与处理

| 风险 | 触发条件 | 处理/降级 | 责任人 |
|---|---|---|---|
| PDF 解析质量低 | 核心字段完整率低于会议阈值 | 保留失败清单，先用 20 篇高质量子集演示，报告限制 | A |
| ES/向量资源不足 | 索引或查询超时 | 降低批量/向量候选，保留 BM25 P0，记录环境 | 组长 |
| LLM API 不可用 | 超时/额度/密钥问题 | 使用固定脱敏证据样例或录屏；明确标记 Mock | 组长 |
| 前后端契约漂移 | 字段/状态码不一致 | 冻结 schema/API 版本，契约测试和通知流程 | 全员 |
| 时间不足 | 10-28 P0 未闭环 | 冻结 P2，确保 20 篇真实闭环、指标和演示 | 组长 |
| 版权/隐私 | 数据来源或日志包含敏感信息 | 只使用允许课堂展示的数据，脱敏日志和路径 | 全员 |
