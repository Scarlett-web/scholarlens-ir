# 个人模型响应与 Agent 异常恢复

2026-10-28。负责人：项目维护者。输入是现有 Chat Completions 适配器、证据 Agent、局部 Harness 和两份参考记录；输出是可复现的响应边界检查及必要修复。这是全局任务中的一项针对性检查，不代表全部审计和设计工作完成。

## 行为契约与验收条件

- 供应商 HTTP 200 不等于可用回答。外层必须是 JSON 对象，具有非空 choices 数组、首项 message 对象和字符串 content；空值、数组、对象、数值、布尔值及无法解析的响应均不得进入回答校验或显示给用户。暂不实现供应商工具调用、视觉内容块或其他协议，其响应必须作为格式不兼容处理。
- 计划和回答中的 JSON 也必须是对象。解析过度嵌套内容时，使用现有受控错误和降级路径，不抛出未处理的递归或属性异常；保留现有响应字节上限、调用时间预算、公共 HTTPS/DNS 固定连接和请求级个人配置隔离。
- 直接问答对格式异常返回脱敏的 502 `ai_invalid_response`；规划格式异常使用原问题检索并记录实际失败步骤；Agent 生成响应异常保留已核验原文，不返回未校验草稿。引用结构异常走现有最多一次修复，仍失败保留原文和提示。
- 不吞掉任意编程异常。仅在外部 JSON/协议边界明确验证形状并归一解析错误，正常文本、代码围栏 JSON、有效引用和现有错误码保持兼容。引文逐字校验不能证明所有回答语义均被证据支持，不将其称为事实正确性证明。
- 使用临时 SQLite、明确 HTTP MockTransport 和虚构模型响应验收，不配置真实个人密钥、不调用外部供应商、不写生产账户或索引。新增失败用例先运行并保留真实失败结果，再修复和复测；将关键恢复行为加入现有局部 Harness。
- 修改后运行针对性后端检查、相关 RAG 兼容用例、Harness 与静态检查。验收后推送并更新既有华为云服务，保留上一 release 和一致性数据库/环境备份；公网仅核对资源、检索及无模型证据模式，不以此替代真实供应商生成验收。

## 实现与证据

- 已复现非字符串 content 和过深 JSON 导致的未处理异常：新增失败用例先在原实现运行，29 项失败，报告和原始输出保留在外层 `output/agent-provider-boundaries-20261028/before.xml`、`before.txt`。这些是供应商格式兼容及异常恢复缺陷，未据此认定越权或数据泄露漏洞。
- 新增 `backend/ai_responses.py`，供计划、回答和引用校验共享 JSON 对象及 Chat Completions 文本形状验证。仅在 JSON 解码边界将 `RecursionError` 转为现有校验错误；没有扩大为吞掉所有运行时异常。保留原有时间、字节、调用次数和引用修复预算。
- 模型返回空值、非文本内容或格式异常时，直接适配器返回脱敏 502；Agent 标记真实失败步骤并返回已核验证据，模型状态为 attempted。计划 JSON 过深时回到原问题，允许正常检索与回答；无效草稿最多修复一次，再失败保留来源，均不泄漏原始供应商消息或未校验草稿。
- `test_ai_responses.py` 与 `test_agent.py` 合计 60 项通过；原有 DNS 私网/混合地址拒绝、Host/SNI 固定、拒绝跳转、上游脱敏及 RAG 错误兼容检查 12 项通过；另单独运行原有正常生成及引用兼容用例 1 项通过。合计 73 项针对性及兼容检查通过，不是后端全量检查。过深/非文本响应、标准及代码围栏 JSON 均有实际用例。
- 局部 Harness 从 8 个扩为 11 个场景，新增格式异常供应商、非文本草稿和过深计划恢复，逐个真实执行均退出 0；结果 `passed=true`、`real_provider=not_tested`、`production_mutations=false`。JSON、JUnit 和输出位于外层 `output/agent-provider-boundaries-20261028/harness/`。
- 官方 MCP SDK 客户端与 stdio 子进程实际检查通过：三工具、两资源、一提示词、私有 ID 和非法数量拒绝。HTTP 数据源为受控本机夹具，真实供应商生成未测试。Ruff 对五个本批修改/新增 Python 文件检查通过，Git diff 格式检查通过。
- 前端源码、依赖、数据库 schema、供应商配置与部署环境均无变更。项目内工具保持局部安装，无新依赖和全局配置变更。发布及公网结果待实际执行后追加。
