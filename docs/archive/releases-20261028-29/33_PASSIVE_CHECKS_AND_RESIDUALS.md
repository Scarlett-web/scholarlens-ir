## ZAP 证据与浏览器资源策略

ZAP 2.17.0 官方跨平台包在校验官方 SHA-256 后放入项目忽略目录。`run-zap-passive.py` 不接受任意目标 URL；只建立它拥有的随机回环端口账户测试实例，使用真实账户/工作区路由、空 SQLite、明确合成论文和实际生产前端。请求计划仅允许 8 个固定 GET，身份挑战在请求前核对，不使用登录、业务写入、爬虫、主动扫描、外部供应商或 ES。实际请求清单与预期状态逐项核对，结束时用户数仍为 0，实例和 ZAP 均退出。

首次结果 `zap-passive-20261028-164626-ef53f40c`：HTML 缺少 CSP 为 Medium/High confidence 告警；这是额外浏览器防护缺口，没有据此认定存在 XSS。现为前端资源响应添加同源脚本/连接、表单和嵌入边界；保留动态 style、头像及本机 Blob PDF。独立 API 和 Swagger 不套用前端 CSP。

复跑 `zap-passive-20261028-165002-6029590d`：执行成功，8 个 GET 全部符合状态，CSP 缺失告警消失。仍有 `CSP: style-src unsafe-inline`（Medium/High）和 `Modern Web Application`（Informational）两类告警。前者为当前 React 动态节点/3D 布局保留的明确折中；没有把它隐藏、标成误报或宣称零风险。脚本与连接仅允许同源，不允许 `unsafe-eval`。以后若要移除内联样式权限，需要迁移实际动态 style 消费者，并单独验证图谱、PDF 和动效。

工具操作异常也保留：首次读取 ZAP 帮助未指定 `-dir`，工具在 `C:/Users/lenovo/ZAP` 创建了默认用户目录。该实例已退出，未删除该目录或其中记录；所有正式检查均强制使用本轮 `reports/.../zap-home`。没有改 Codex/MCP、浏览器登录或系统代理。
