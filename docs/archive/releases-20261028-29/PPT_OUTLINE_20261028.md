## 推荐图表

1. **架构图**：直接使用总报告 Mermaid 图，导出为 SVG；不要把密钥、内网地址和用户数截图。
2. **搜索对比图**：同一查询分别展示 keyword/semantic/hybrid 的前 5 条，标注模式而不是比较分数大小。
3. **状态机图**：上传 `pending → approved/rejected → processing → indexed/failed`，旁边标“独立索引，不覆盖基础库”。
4. **证据链图**：问题 → 检索片段 → chunk/locator → quote 逐字核验 → 可引用回答。
5. **质量矩阵**：将“已验收 / 部分覆盖 / 待验证”分开，避免把 Mock、fixture 和公网真实检查混成一个绿色勾。

## 讲稿口径

- 把“真实”限定到数据、接口、范围和日期，例如“截至 2026-10-28，公网只读核对显示 859 篇”。
- 把“支持”与“已验收”分开，例如“保留个人 AI 配置接口，但真实供应商生成尚未验收”。
- 把“性能”限定为测量条件，例如“本机/服务器顺序三次测量，不是并发压测”。
- 不展示账号、token、API key、服务器环境文件、用户数据库、完整原始论文包路径。

## 逐页可复制正文与讲稿

以下文字可直接放进 PPT，再按自己的表达缩短。每页推荐 3–4 个信息点，长段“讲稿”放演讲备注。成员、班级、课程教师和个人分工由你按实际情况填写。

### 第 1 页｜ScholarLens 学术论文研究工作台

**页面正文**

- 信息检索课程项目：从“找到论文”到“核对证据”。
- 真实文献、三模式检索、原文阅读、私人整理与受审核上传。
- 在线入口：`https://scholarlens.lingion.cc.cd/`。
- 汇报日期：2026-10-28；团队成员：按实际填写。

**配图**：使用[首页实拍](../../assets/report-20261028/01-home.webp)，标题覆盖空白区；保留域名，二维码应从该真实 URL 生成。

**讲稿**：这次展示的 ScholarLens 已经能通过公网域名使用。它围绕“搜索、阅读、整理、核验”组织功能。下面先介绍真实数据与架构，再演示如何完成一次研究操作，最后说明验证范围和还没有完成的部分。

### 第 2 页｜我们希望解决什么问题

**页面正文**

- 只搜到标题，不能方便地回到原文。
- 看过的论文、摘录与笔记容易散落。
- 关键词与自然语言问题的匹配方式不同。
- 生成式回答需要可复核的原文依据。

**配图**：四个问题对应四个模块，避免加没有依据的用户调查百分比。

**讲稿**：课程作业需要验证检索原理，但实际使用还需要把结果接到原文和个人研究空间。我们的重点是把这些动作连接起来，同时保留数据来源和错误反馈，避免只有界面、缺少可追溯链路。

### 第 3 页｜围绕研究任务组织产品

**页面正文**

- 找到：六字段和三模式检索。
- 看懂：摘要、正文、PDF 与专注阅读。
- 留存：收藏分类、笔记、历史和备份。
- 核对：原文片段、引用定位和执行记录。
- 持续运行：账户、审核、服务器与回滚。

**配图**：五步横向流程，结束后回到搜索，体现可继续研究。

**讲稿**：这些目标决定了页面和后端的划分。界面不是单独做一个漂亮首页，而是每个入口都有对应的真实数据、操作和失败状态。后面的演示也按这个顺序展开。

### 第 4 页｜现在已经拥有的项目资产

**页面正文**

- 正式检索库：859 篇真实论文；基础向量片段：49,420。
- 正式库 859 份 PDF：合计 22,686 页。
- 原包 999 份：独立 GitHub 数据 Release 存档。
- 完整前后端与在线部署；个人模型和邮件保留配置边界。

**配图**：做 4 张数字卡；“999 原包”与“859 正式库”用不同标签。

**讲稿**：这三个数量分别描述原始材料、进入检索库的论文和语义片段，不能混用。正式 JSONL 来源于数据组的处理成果，本会话在此基础上完成校验、索引、集成和后续功能，不能把这些都说成重新解析了全部原包。

### 第 5 页｜前端、API 和数据各自独立

**页面正文**

- React/Vite/TypeScript：研究界面与浏览器交互。
- FastAPI：统一接口、鉴权、任务和证据工作流。
- Elasticsearch：关键词、向量及排名融合。
- SQLite：账户和私人研究数据；PDF/模型独立存储。

**配图**：使用[总报告第 4 节](PROJECT_REPORT_20261028.md#4-系统架构)的架构图，外层加 Cloudflare Tunnel。

**讲稿**：浏览器通过同一个 HTTPS 域名访问静态界面和 API。论文索引、用户数据库和原件分开保存，浏览器不直接访问 Elasticsearch。这样既方便课程项目部署，也让版本切换不必覆盖用户和论文数据。

### 第 6 页｜数据可信比数据“看起来完整”更重要

**页面正文**

- 固定数据提交、稳定 paper_id 和来源清单。
- 全量字段校验，再做 20 篇先行验收，最后全量发布。
- 4 篇严重乱码正文隔离，仍保留论文和元数据。
- 新索引完整成功后才切换 alias；旧代和原件保留。

**配图**：数据链路图 + 小型完整率图，标题 100%、作者 99.77%、摘要 89.99%、安全正文 99.53%。

**讲稿**：缺少字段时我们保持空值，不从正文猜日期或作者。partial 不等于整篇失败；严重乱码则只隔离正文，不删除来源。原 PDF 与 JSONL 也分别核验，因为解析文本不能还原原排版。

### 第 7 页｜三种检索模式

**页面正文**

- BM25：精确词与字段检索，k1=1.2、b=0.75。
- 语义：MiniLM CPU ONNX，384 维，真实片段召回。
- 混合：RRF(k=60)，融合排名而非直接相加分数。
- 相同语料和查询条件下可比较；尚无正式效果提升百分比。

**配图**：BM25 / Semantic / Hybrid 三列机制图；RRF 公式见总报告第 16 节。

**讲稿**：精确字段适合 BM25，自然语言问题可能需要向量语义。混合使用两路排名，避免不同分数尺度直接相加。我们的系统支持实验对比，但没有用单条成功案例来证明混合总是更好。

### 第 8 页｜搜索结果是可操作的文献记录

**页面正文**

- 标题、作者、日期、机构、地址、正文六字段。
- 搜索建议、年份筛选、排序、分页和 URL 分享。
- 高亮、阅读、收藏和查看原文证据在结果旁可发现。
- 无结果、加载失败、非法页码和模式限制都有明确反馈。

**配图**：[搜索页快照](../../assets/report-20261028/02-search.webp)是空查询的真实近期候选；若要演示关键词结果，现场搜索 `magnetic` 后再截图。

**讲稿**：搜索结果不只是几张装饰卡片。筛选条件进入 URL，修改后回到第一页；结果数和耗时来自当前请求。空查询候选浏览会明确写明范围，不冒充全库检索。

### 第 9 页｜让阅读能接着上一次继续

**页面正文**

- 摘要、正文窗口、全文查找、PDF 与文本 DOCX。
- 专注模式：收起导航，实色纸面、明确退出。
- 保存本机阅读位置，用户主动恢复。
- 真实选文追加笔记，保留旧笔记，不静默截断。

**配图**：[专注阅读实拍](../../assets/report-20261028/03-focus-reader.webp)。

**讲稿**：背景和导航有玻璃材质，但正文不透背景，优先保证长文可读。位置只表示滚动位置，不代表读懂或读完；它是当前浏览器保存的记录，也不冒充跨设备阅读进度。

### 第 10 页｜我的文献是一张研究书架

**页面正文**

- 收藏分类创建、重命名、删除；论文与笔记并列。
- 搜索历史和浏览历史分开，最近五篇只来自真实阅读。
- 登录工作区服务端同步，失败保留本机恢复草稿。
- JSON 导入导出有明确替换提示。

**配图**：用自己的专门演示账号，放 2–3 条无隐私笔记；不要展示生产用户历史或把 fixture 当真实使用记录。

**讲稿**：整理动作需要可靠反馈。我们区分“正在读取”“读取失败”和“确实没有收藏”；同步失败时保留已知内容并允许导出，避免看见空页就误以为数据丢了。

### 第 11 页｜账户和权限在服务端生效

**页面正文**

- 登录、退出、资料、头像、改密、停用和会话撤销。
- 密码 scrypt、会话 token 哈希，不存明文密码/token。
- 普通用户/管理员分权；私人文件和对话按拥有者隔离。
- 最后一名有效管理员有事务与并发保护。

**配图**：总报告第 19 节权限矩阵，取 5 行即可。

**讲稿**：隐藏按钮并不能证明权限正确，所以我们用真实 SQLite 和真实路由检查身份、所有权及会话失效。另一个具体修复是输错当前密码不能误退出；只有真实会话失效才清理当前登录。

### 第 12 页｜上传不是直接写进基础库

**页面正文**

- 提交 → 待审核 → 批准/拒绝 → 解析处理 → 索引成功/失败。
- 202 只是任务接受，最终状态通过轮询确认。
- 关键词和向量发布独立 generation，保留基础 859 篇。
- 归档保留文件与审计，不等于物理删除或撤稿。

**配图**：总报告第 15.8 节状态图，或用 6 个方块表现工作流。

**讲稿**：文件校验、审核和索引发布分开，失败不会覆盖已有库。当前本地文本 PDF 解析可用，扫描件需要 OCR；GROBID 外部结构化解析仍需单独接入和验收。

### 第 13 页｜证据助手优先给可核对来源

**页面正文**

- 问题 → 真实片段 → 原文核验 → 引用/定位/笔记。
- 来源包含 paper、chunk、字段和 Unicode 字符范围。
- 引用不匹配或供应商失败，保留原文证据。
- 无模型配置仍可检索证据；真实模型生成未验收。

**配图**：证据链流程，不必为了截图填个人 API key。

**讲稿**：我们能检查引用确实来自某个片段，但不能据此宣称所有回答语义都正确。证据台把原文和轨迹直接显示出来，让使用者有机会回去核对，而不是只信一段回答。

### 第 14 页｜Agent、MCP、Skill、Workflow 各司其职

**页面正文**

- Skill：工具白名单、输出和核验规则。
- Workflow：预算、步骤、证据数、修复次数。
- Agent：实际检索/核验与有限规划，记录真实轨迹。
- MCP/Harness：局部只读协议与可复现案例。

**配图**：四层职责图；注明 MCP 3 工具/2 资源/1 提示词，Harness 11 个受控案例。

**讲稿**：这不是静态画出来的流程图，运行时会读取规则并执行工具。但它也不是能任意调用系统的通用代理：工具和次数受约束，没有调用的步骤不显示为完成，MCP 不接收密钥和任意远程 URL。

### 第 15 页｜视觉与交互围绕可读性收敛

**页面正文**

- 冰岛实景 + 清澈玻璃导航 + 明亮纸面正文。
- 首页搜索首屏可见，移除突兀悬浮与重复容器。
- 登录、搜索、书架、证据台以明确动作和状态组织。
- 3D/CSS 深度、轻路由转场；暂停和减少动态始终可用。

**配图**：首页/专注阅读两图对照。若没有旧版截图，只讲当前改动，不伪造“之前”。

**讲稿**：我们根据实际反馈调整过搜索位置、玻璃透明度和悬浮层。最终重点是让主操作能看见、正文能读清、状态能理解；动效服务于层次和反馈，不让它持续打断阅读。

### 第 16 页｜几项具体问题如何修复

**页面正文**

- 错误二次凭证导致误退出 → 区分 invalid_credentials / unauthenticated。
- 管理员并发变更可能归零 → 同一写事务内计数、复核、变更。
- API-only 私有文件缺 no-store → 响应头中间件独立生效。
- 旧请求污染新上下文 → 身份/筛选/focus 与请求令牌隔离。

**配图**：四行“触发—修复—证据”表，替代抽象“安全可靠”。

**讲稿**：这些问题有明确触发条件，修复前能在隔离环境复现，修复后有针对性测试。我们还增加了同源 CSP 和依赖公告检查，但没有把这称为全站安全认证。

### 第 17 页｜质量验证有数字，也有范围

**页面正文**

- 前端 35 项；独立后端模块 135 项。
