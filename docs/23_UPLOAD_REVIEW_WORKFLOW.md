# PDF 工作区与审核流程契约

2026-10-28；负责人：项目维护者。依据 GPT Pro 记录的 PDF 工作区及审核页建议，改进选文件、提交、进度与审核决策的可读性。保留后端权限、状态机、原始 PDF 和独立上传索引，不对生产写测试文件或审批记录。

## 输入、输出与边界

- 输入为既有上传 API 的原始状态：pending、approved、rejected、processing、indexed、failed、dependency_unavailable，及 created_at、updated_at、reason、attempts、paper_id。没有额外的阶段日志，不猜测各阶段的时间。
- 流程线为“收到 PDF → 审核 → 解析与关键词入库 → 可检索”。后端 processing 合并解析和索引，前端不得将其拆成虚假的已完成步骤。拒绝、失败、依赖不可用和未知状态明确显示原因及下一步；关键词入库不代表向量已完成。
- 上传页为文件入口及右侧账户/流程说明；选文件后确认提交，可取消或替换。拖放有反馈，未登录用户可切换本机文件；不弹出覆盖主体的登录卡，不使用假百分比。
- 审核页用真实本页统计、筛选、原因、状态线与明确动作组织队列。仅有总记录数是服务端全量统计，状态计数和筛选必须标注本页。批准、拒绝、处理、预览、DOCX、打开论文、归档均保留。
- 自动刷新串行执行，可取消旧查询；成功恢复后清除旧加载错误。队列、草稿、选择文件和 PDF 预览按当前账户与角色隔离，账户变化后不得显示前一账户内容。异步预览返回时也校验账户。
- 不添加图形/动画依赖，使用现有系统字体、图标及 canonical CSS，动态只表达拖入、提交和真实处理状态，支持暂停与 reduced motion。

## 验收条件

运行生产构建、现有测试与结构检查；状态测试覆盖拒绝、失败、依赖缺失、未知状态及入库边界。独立浏览器通过明确标记的接口 fixture 验证游客、研究账户和管理员队列，覆盖确认提交、失败恢复、串行刷新、状态筛选、操作请求和账户过期隔离，fixture 不计为真实后端端到端。真实 API 游客回归单独运行，生产只读验收。查看桌面截图，390px 仅布局回归。完成后将源码和记录推送并部署既有华为云服务，保留旧 release、数据库与环境备份，验证公网资源及真实论文库。

本批不代表总审计完成；其余逐页设计、证据加入笔记、个人供应商生成、隔离被动扫描和安全边界继续按原始目标推进。

## 实现与验证结果（2026-10-28）

- 选文件、确认提交、取消与替换分开；空文件、扩展名和 20 MiB 上限在提交前检查，实际内容仍由后端校验。拖入和请求等待有状态反馈，不显示虚构百分比。审核页保留批准、拒绝、解析、原文预览、DOCX、论文链接、向量重试、归档和分页。
- 队列总数来自后端；状态计数、文件名和状态筛选明确只作用于本页。未知状态不会被推断为已批准或处理完成；状态与原因映射也覆盖对象原型键，防止 `constructor`、`__proto__` 变成错误标签。
- HTTP 202 只提示“处理任务已提交，完成状态以队列为准。”，不会声称入库完成。关键词入库与向量状态分别表达。未登录时没有私有队列请求，未知数量用破折号。
